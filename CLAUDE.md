# CLAUDE.md — snipeit-mcp

**Company context comes first: read [../mojood-master/CLAUDE.md](../mojood-master/CLAUDE.md) and
[../mojood-master/STATUS.md](../mojood-master/STATUS.md), then this file.** Never add a `Co-Authored-By` line (or
any Claude attribution) to a commit message or a pull request description.

**What's here:** a Mojood Connect demo, built for one company (Grokability, makers of Snipe-IT) to show them their
product working inside Claude. Six tools over Snipe-IT's REST API; the two that change records need a confirmation
code (`tools.py`). A local Snipe-IT in Docker (`docker/compose.yml`, `scripts/up.sh`, `scripts/reset.sh`) holds
SAMPLE data for the made-up Harbor Trading (`seed.py`). Private until Hammad sends it; public (Apache-2.0) after.

## Commands
```
scripts/reset.sh                         # fresh local Snipe-IT + SAMPLE data (Docker via Colima: `colima start`)
uv run --env-file .env snipeit-mcp       # http://127.0.0.1:8002/mcp ; add --stdio for Claude Desktop
uv run --env-file .env pytest            # unit tests + live tests against the local Snipe-IT
uvx ruff check --line-length 120 src tests
```

## Rules
- Secrets (`.env`, `docker/.env`: the API token, the admin and database passwords) are generated by `up.sh`,
  git-ignored, and never printed, copied into docs or chat.
- Every figure in the data is SAMPLE and made up; no real company's data goes in.
- A change tool never acts without its confirmation code; keep the tests in `tests/test_tools.py` passing.
